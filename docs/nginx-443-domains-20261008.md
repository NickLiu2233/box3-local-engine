# HTTPS 统一 443 与独立域名

> 历史方案：下文的固定 443 和地址限制已被后续配置规则替代，不作为当前操作依据。当前说明见[Nginx 指南](./https-certificate-management.md)。

日期：2026-10-08；版本 v0.3.0。本轮按用户要求替换上一轮的自动高端口方案。

界面所有 HTTPS 路由默认使用 443，拒绝其他显式 HTTPS 端口。多个服务使用独立域名，Nginx 通过 server_name 共用同一 443 监听。用户确认自行填写现有独立公网地址，不生成或修改真实域名、DNS 或用户部署配置。

共用证书可继续用于多个独立域名，但必须覆盖各域名。同一域名被多个服务继承时，在保存前提示填写不同域名，不先写入配置后报失败；未保存的表单和证书选择保留。移除 13121 等自动端口分配及提示。启用已保存入口也依据当前公网地址重新生成 443 路由。

引擎原 HTTP 端口保持不变。启动器 HTTPS 链接省略默认端口，管理端生成的公网 URL、登录 URL 和 CORS 根据保存的托管域名和 443 监听更新。旧 API 自定义端口仍保留兼容，但界面采用新规则。

验证：界面与传输 44 项通过，共享后端 99 项通过、2 项 Docker 验收默认忽略。真实隔离验收验证两个域名共用 Nginx 内部 443、HTTPS、WSS echo、错误私钥保留、重载及外部配置导出；宿主机使用随机测试端口避免影响真实 443。界面结构和生产构建、Web 管理端离线编译检查通过。

证书域名覆盖、DNS 指向和真实本机 443 可用性需在用户配置后现场验证。没有重建六服务镜像、部署运行中的 Web 管理器或重启业务容器。安装包属于包含未提交修改的 macOS ARM64 测试候选包，ad-hoc 签名，未 Apple 公证。

补充验收：两个域名分别转发到不同隔离上游，验证 server_name 分流。公网测试端口为随机映射，Nginx 内部只有 443 监听。

## 修复的行为差异

- 环境变量统一处理注释、空格、重复键及包含等号的值。
- 两端采用相同配置类型和范围校验；兼容 IPv6、旧公开 URL、HTTPS 与外部数据库查询参数，表单修改对应配置后撤销旧覆盖。
- Web 返回完整许可证状态并采用相同可信时间检查；保留历史设备 ID 规则。
- 统一服务范围和依赖启动顺序。配置错误不再阻断状态查询和停止；Docker 查询失败显示未知状态及原因。
- Web Compose 使用真实宿主机部署路径，避免将容器内 `/workspace` 当作宿主机挂载源。
- 新备份统一 PAX tar.gz，兼容历史 ZIP、TAR、GNU/PAX 长路径。先校验再停止和恢复，拒绝路径越界、链接和特殊文件；替换目录内容并保持挂载根目录 inode。
- 同名导入不覆盖，发布文件权限为 Unix 0600；恢复清理告警与恢复失败分别展示。
- Web 长操作拥有经过鉴权的进度接口，后台读取不污染进度；过期请求的 401 不会删除更新后的令牌。
- 登录表单布局、平台提示、外部链接、备份选择及下载集中适配。

共享核心测试覆盖真实归档往返、历史 ditto ZIP、中文长路径、恢复回滚、配置迁移、许可证签名与时间、服务编排。共享核心 79 项、桌面 25 项、Web 16 项、前端传输 8 项测试通过；桌面/Web 静态检查、许可证边界、文档检查和 Vite 生产构建通过。

隔离目录中的实际 HTTP 验证已确认鉴权、创建/下载/上传、损坏归档拒绝、同名不覆盖、恢复清除旧文件、保持根目录 inode 及完成进度。测试使用模拟 Docker，未操作真实容器或用户数据。浏览器验证了共用页面的登录与许可证入口。

系统密钥、硬件发现、镜像供应、诊断收集及网络执行仍由平台适配器承担。未执行真实 Docker 部署、Windows/Linux 原生窗口验证或真实业务数据恢复。文件备份不是数据库事务快照，恢复回滚不保证断电原子性。

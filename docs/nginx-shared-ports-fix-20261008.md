# 共用 HTTPS 地址与内置 Nginx 端口冲突修复

日期：2026-10-08；版本 v0.3.0。

本记录是历史方案，后续已按用户要求改为各服务独立域名统一使用 443，不再自动分配高端口；当前规则见 https-certificate-management.md。

## 原因及复现

共用 HTTPS 地址沿用了 BOX_PLAY_PORT 等引擎宿主机 HTTP 端口。内置 Nginx 也尝试监听这些端口，实际保存流程先写入地址，再被后端端口所有权检查拒绝，显示“配置已保存，但后续应用失败：Nginx 端口与引擎服务端口冲突”。切换状态确实是 managed，五个引擎端口本身没有重复。

修复前执行 `node --test --test-name-pattern='shared HTTPS save' scripts/deployment-manager-ui.test.js`，保存回归测试失败并产生同样的端口冲突提示；修复后相同命令通过。

## 修复

- 内置模式下无显式端口的共用 HTTPS 地址分配独立 TLS 入口。默认对应引擎端口加 10000，跳过引擎端口、管理端口和独立 HTTPS 地址的端口；溢出时从 10000 开始分配。
- 默认游玩端 13121、创作端 13127、VOXA 13123、账号后台 13124、登录页面 13125。共用证书区域显示实际分配结果及公网端口放通提示。
- 引擎宿主机端口及 Docker 网络内 HTTP 上游不变。启动器链接使用 TLS 入口；桌面与 Web 运行时环境根据保存的 managed routes 更新公网 URL、登录链接及 CORS 白名单，局域网／本机模式和已切换的外部提供者不被旧托管配置覆盖。
- 独立 HTTPS 地址和外部 Nginx 的原有端口规则保持不变。后端端口冲突检查保留，避免显式配置错误占用引擎端口。

## 验证

界面与传输 44 项通过；共享后端 99 项通过、2 项原有隔离验收默认忽略。内置 Nginx 隔离验收另行执行并通过，真实验证同一个证书域名的两个独立 TLS 端口、HTTPS、WSS echo、错误私钥保留、重载及旧外部导出。界面结构及生产构建、Web 管理端离线编译检查通过。

没有导入用户真实证书、修改用户部署地址或重启业务服务。截图中的证书文件名不能证明是否覆盖 user.box3lab.com，实际保存仍会检查证书域名、有效期及私钥。更新公网 URL 后需要重新启动相关引擎服务，且公网防火墙／路由需放通界面显示的 HTTPS 入口。

这类问题应通过“公网 URL、TLS 监听端口与引擎 HTTP 上游分别验证”的端到端回归防止；此前只测独立域名 443，没有验证共用地址与原服务端口同时存在的场景。

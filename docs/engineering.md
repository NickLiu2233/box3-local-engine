# 工程规范

- 自有 TypeScript/JavaScript 使用统一的四空格、分号、单引号、分支花括号和类型注解规则；目录范围、package.json 顺序和例外见[代码风格](./code-style.md)。提交前运行格式化、lint、类型检查和测试。
- 三个界面的职责划分和验证入口见[应用代码维护](./application-code-maintenance.md)。上游同步文件保持各自约定，不用全局替换改动协议或生成代码。
- 新增或完整整理的业务代码文件以 500 行为上限；按完整职责拆分并优先复用，不能靠压缩代码或制造大量碎文件满足行数。当前入口见[应用代码维护](./application-code-maintenance.md)，[第一轮记录](./engineering-refactor.md)只保留历史背景。
- 服务端负责权限、存档、奖励和判定；客户端代码和资源一律视为不可信。
- 永久地图 ID、地图组关系、Blob hash、发布清单和协议是兼容接口，修改必须有回归。
- `.env`、用户项目、地图、备份、日志、Docker 数据和构建产物不进入 Git。
- 不通过隐藏前端按钮实现权限控制；服务端 API 必须独立校验身份与授权。
- Docker 镜像中的运行时代码必须以最终镜像为准验证；涉及运行时采样、启动流程或打包层时，不能只检查宿主机源码或 Docker 缓存。
- 公开发行物必须从干净的 Git Tag 构建；版本、提交、日期和来源由 CI 写入 `BOX_BUILD_*`，不在 UI 中硬编码或手工伪造。
- App、镜像归档与清单必须来自同一次构建；发行前在干净环境验证最终离线包，而不是只验证工作区。

唯一的全量验证命令：

```bash
rush verify
```

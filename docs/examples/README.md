# 地图反作弊示例

这些示例只用于**服务端脚本**。合并到自己的地图代码，不要覆盖原来的玩法，也不要直接放进客户端脚本。

## 先观察数据

[anticheat-observe.js](./anticheat-observe.js) 包含 8 个事件的用法。默认只记录移动和操作，且不打印日志；按需要修改 `enabledEvents` 和 `printLogs`。它不会拒绝、踢人或封号。

## 开始写规则

[script-anticheat.js](./script-anticheat.js) 把规则判断、记录和处理分开，每条规则有自己的记录器。默认没有检测条件，只观察。

1. 在 `movementRule` 或 `actionRule` 中写自己的判断。
2. 正常返回 `null`，异常返回 `{ reason, points, reject }`。
3. 先保留 `observeOnly: true`，确认正常玩家不会误判。
4. 再改成 `false`，允许规则拒绝本次操作。不会自动封号。

不要同时原样运行两份示例，否则会重复订阅和记录；选一份作为起点，再合并所需片段。

## 修改前先知道这些

- `player` 来自服务器识别的连接，客户端不能用消息字段替换它。
- 候选位置、射线、目标、客户端 tick 和自定义事件内容仍不可信。
- `onMovement` 拒绝本次位置/速度修正，普通按键保留；其他分类监听拒绝相应消息。`onAction` 拒绝整条输入消息。
- 回调必须同步，不要在里面 `await`。异常和超时会拒绝，即使示例设为只观察。
- 服务端技能可设置本规则的临时豁免，但必须先验证技能条件；不能直接接受客户端的豁免请求。
- 记录器的容量不是玩法限制，也不是某个时间窗口的完整计数。高频记录会挤掉旧样本。
- 没有通用的“正常速度”或“正常射线距离”。按自己的相机、武器、冲刺、载具和传送设计规则。

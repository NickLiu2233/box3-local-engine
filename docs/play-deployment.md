# 游玩端部署

Play 运行已发布的 `.boxplay`，不读取 Creator 源工程。桌面用户用启动器启动；源码环境使用：

```bash
node apps/local-engine/src/deploy.js play
node apps/local-engine/src/deploy.js play-up
```

## 必需条件

- Player Service 与 PostgreSQL 已启动。
- 设置 `PERMISSION_TOKEN_SECRET`、`BOX_PLAYER_AUTH_API_KEY` 和 `BOX_PLAY_ADMIN_TOKEN`。

## 地图管理

使用玩家管理后台的“游玩管理 → 游玩地图”导入、审查、启停、设置访问 ID 或删除地图。游玩端首页不再提供服主管理入口；拥有游玩地图权限组的管理员也可执行已授权操作。

### 本地资源加速

默认关闭。服主或管理员可在“游玩管理 → 本地资源加速”开启。开启后，Play 从发布包的 `runtime-blobs.json` 建立资源清单，并排除 `private-blobs.json` 列出的私有 Blob。清单包含当前已发布地图引用到的公开地形数据、模型、贴图、图片、音频和其他静态 Blob，以及已生成的运行时派生资源；它只覆盖同源、内容寻址的 Play 资源。

浏览器用 Cache Storage 保存经校验的响应，缓存名为 `box-play-static:<永久地图 ID>:<资源版本 hash>`。资源版本 hash 根据永久地图 ID、地图发布版本和已排序的公开资源 hash 计算；重新发布、资源增删替换或新增派生资源都会生成新版本。新版本会替换同一永久地图的旧版本缓存，不同地图彼此隔离。

玩家首次进入时，地图加载与后台预取并行进行：已命中的资源优先读取本地副本；尚未写入的资源会正常走网络，后台再继续补齐。因此“首次进入可用”不等于“当前设备已完成全部资源落盘”；页面过早关闭也可能使预取尚未完成。资源不存在、下载中断、校验失败或发布版本改变时，运行时同样回退在线资源，缓存故障不会阻止玩家进入地图。

`private-blobs.json` 是发布包的私有资源 hash 列表。它包含脚本源码、权限、协作者、版本控制和其他敏感发布控制数据；运行所需的脱敏脚本索引不等同于脚本源码。Play 的公开 Blob 路由会拒绝这份列表中的 hash，本地缓存清单也会在下发前排除它们。客户端脚本、服务端脚本、私有发布控制数据、登录信息和实时房间数据不会被该功能持久化。Play 会为资源清单签名，浏览器只会写入签名有效且内容 hash 匹配的响应；关闭开关后，玩家会回到在线资源读取，浏览器中已有的该服务器静态缓存会在下一次进入地图时清理。

服主通过密钥进入管理页，导入前可审查地图组、代码、图片和音频；确认后才安装。主地图与副地图会作为同一地图组运行，在线人数汇总到所属主地图。Play 只能开关或删除地图，不能编辑发布信息或导出地图包。

地图库由 `BOX_PLAY_LIBRARY_DIR` 决定，端口只改变访问地址。Teleport、预热和运行时上限使用 `BOX_PLAY_MAX_RUNTIMES`、`BOX_TELEPORT_MAX_ROOMS`、`BOX_RUNTIME_IDLE_TIMEOUT_MS` 等变量配置。

Play 和登录门户可通过 HTTPS 反向代理面向玩家公开。Linux 无图形服务器同时携带创作端服务，服主可按需启用；不需要远程创作时保持 Creator 与 VOXA 关闭或仅本机监听。

## 启动与检查

启动后访问 Play 首页，确认地图列表、登录跳转和地图进入正常。排查顺序应为：容器健康状态、Player Service、发布包审查结果、Play 日志、地图运行时日志。不要先删除 Docker 卷或地图库。

Play 地图目录可持续保存多个主地图和副地图。运行时启动失败通常与发布包资源不完整、脚本错误、地图过大或运行时额度不足有关；重新发布/导入前先保留失败日志。

## Linux 服务器

无图形包包含 Creator、VOXA、Play、玩家服务、登录门户和 Web 管理端，但没有迁移器或内置数据库。管理端拥有 Docker 控制能力，应仅监听回环地址并通过 SSH 隧道或 VPN 访问。

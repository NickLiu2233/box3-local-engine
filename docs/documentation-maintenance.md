## 分类规则

- **当前指南**：说明当前使用、实现或开发要求；行为变化同步更新。
- **历史验收**：保留原日期、样本、平台和结论；页首链接当前指南，不追写新测试结果。
- **设计与规划**：明确未实现或已替代的能力，不能作为当前安装步骤。
- **验证记录**：区分源码、局部构建、模拟网络、全仓 Verify 和最终发行包验收，只报告执行过的检查。

保留现有路径以免破坏外部引用，通过索引分类和页首状态消除歧义。

## 更新检查

1. 新专题同步索引，应用维护说明通过对应专题或项目入口链接。
2. 服务、默认协议、Cookie、权限、存储和发行入口变化同步指南与示例。
3. JS/TS 示例遵循自有规则；JSON/YAML 遵循各自语法，示意片段不伪装成可执行命令。
4. 源码、安装包、运行容器和 CDN 分开描述，不由源码日期推断部署状态。
5. 测试失败注明阶段，不能以旧统计替代本轮验证。
6. 不提交密码、Cookie、Token、玩家信息、数据库备份或本机原始报告。

```sh
npm run format:owned:check
node scripts/check-documentation.js
git diff --check
```

格式检查覆盖自有应用说明、根 README/贡献指南和全部 `docs/`。文档检查使用 Markdown 解析器检查本地直接链接、图片、引用式链接，以及索引、版本与发行边界；日期历史文档必须在页首标注历史状态，登录模板示例版本与项目清单一致。生成产物和私有运行数据不进入文档扫描。它不联网验证外部链接，不验证标题锚点、公网部署或每段示例的业务结果。

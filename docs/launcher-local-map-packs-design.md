# BOX3玩家启动器

> **已被当前方案替代（2026-09-30）**：本文后续内容记录的是旧的“本地地图包 + `boxplay://`”设计，不再作为实现依据。当前架构以 [玩家启动器 Service Worker 资源缓存](./launcher-service-worker-cache.md) 为准：不使用自定义资源协议，不做离线包导入，静态地图资源由同源 Service Worker 缓存；服主无需配置资源访问开关。

## 1. 背景与结论

浏览器 Service Worker 缓存和启动器本地地图包解决的是不同问题：

| 能力     | 浏览器 Service Worker 缓存 | 启动器本地地图包                 |
| -------- | -------------------------- | -------------------------------- |
| 安装要求 | 无；普通浏览器即可         | 需要安装 BOX3 玩家启动器         |
| 首次进入 | 可以边下载边进入           | 启动器自动补齐，完整后进入       |
| 资源来源 | 浏览器 Cache Storage       | 启动器受控的本地内容库           |
| 缓存丢失 | 浏览器可能因配额或清理删除 | 由启动器显式显示、修复和清理     |
| 联机     | 正常连接服务器             | 正常连接服务器；仅静态资源走本地 |
| 目标     | 渐进式加速                 | 可预测的“已安装地图”体验       |

## 2. 范围

### 目标

- 玩家可从启动器下载或导入服务器认可的 Play 地图版本；
- 地图的公开静态资源在本机内容库中按 hash 去重存储；
- 启动前校验永久地图 ID、发布版本、资源清单、签名和每个 Blob hash；
- 缺失、损坏、签名无效或版本不匹配时，启动器自动下载或修复；所有必需资源验证完成前不进入地图；
- 启动后地形、模型、贴图、图片、音频、UI 静态数据等从启动器本地协议读取；
- 玩家仍连接远端服务器完成登录、房间分配、实体同步、聊天、持久数据和权威游戏逻辑；
- 多张地图或多个版本使用同一个内容 hash 时，本机只保存一份 Blob。

### 玩家导入方式

启动器只提供两种面向玩家的地图导入入口：

1. **在线导入**：玩家输入游玩服务器的 HTTPS 地址、IP 或域名；启动器验证服务器身份并列出可游玩的地图。选择地图后，自动下载缺失资源并启动联机。（需要后台开启该功能)
2. **本地导入资源**：玩家选择管理员或服务器分发的已签名资源包；启动器验证签名并把其中公开资源写入本机内容库。之后连接对应服务器时，已存在资源自动复用，无需再次下载。

本地导入不是把任意 `.boxplay` 当作可执行地图。玩家资源包只包含签名描述符和公开静态 Blob；服务端脚本、权限、账号数据和运行时状态不在其中。

### 非目标

- 不把服务端脚本、数据库、账号、权限、实时房间状态或管理密钥放入玩家设备；
- 不允许普通网页通过 `127.0.0.1` 或文件路径任意读取玩家本地资源；
- 不用本地包替代服务器权威判定；
- 不将浏览器 Service Worker 改造成严格资源门禁；

### 服务器级玩家启动器授权

“在线导入”不是任何人输入 IP 后都能读取服务器地图的公开能力。服务器提供一个独立的**玩家启动器**开关，默认关闭；只有服主或管理员可以在后台管理中开启或关闭。它与“本地资源加速”类似，影响的是所有玩家设备上的资源分发策略，但两者是独立功能：浏览器 Service Worker 缓存开启不等于允许玩家启动器下载地图包。

开启后，已登录且有权游玩目标地图的玩家才可通过启动器：发现可游玩地图、获取签名描述符、请求下载计划和下载公开资源。关闭后：

- 启动器不得列出地图、获取描述符或下载 Blob；
- 本地已存在的资源包不能绕过服务器获取联机启动票据；
- 玩家看到“该服务器未开放玩家启动器资源下载”，而不是权限字段或内部接口错误；
- 普通浏览器 Play、服务器权威逻辑和现有 Service Worker 缓存开关不因此改变。

建议 capability 命名为 `play-launcher-resources.view` / `play-launcher-resources.manage`，并与本地资源加速一样仅内建给服主和管理员，不可通过普通权限组转授。

## 3. 术语与不变量

### 术语

- **地图包描述符（Map Package Descriptor）**：服务器签名的、小型 JSON 文档，声明一个可安装地图版本及其资源清单。
- **本地地图包（Local Map Package）**：描述符已验证、全部必需 Blob 已存在且 hash 校验通过的本机安装状态。
- **必需资源（required asset）**：启动或运行该发布版本必定需要的公开静态资源。
- **可选资源（optional asset）**：不影响进入和核心运行的预览、说明图或可延后下载资源。
- **启动票据（Launch Ticket）**：服务器为当前登录玩家、地图版本和短时有效期签发的联机启动授权。

### 不变量

1. 一个本地包由 `(permanentMapId, releaseVersion, manifestDigest)` 唯一标识。
2. 地图可启动当且仅当所有 `required` 条目存在、内容 hash 匹配且描述符签名有效。
3. 本地资源协议只能读取当前启动会话允许的地图版本和清单内 hash，不能按任意路径读取磁盘。
4. 联机服务器和启动器必须使用相同的 `permanentMapId`、`releaseVersion`、`manifestDigest`；不一致即拒绝加入。
5. 服务端脚本永不出现在描述符或本地内容库中。
6. 资源完整性校验不能依赖文件名、扩展名或“下载成功”标志，只能依赖内容 hash。

## 4. 模块与 seam

设计采用少量深模块，避免把校验、下载和路径规则分散到启动器页面、WebView 和服务端调用点。

### 4.1 启动器 `LocalMapPackageManager`

这是启动器侧的核心 Module。其 Interface 保持小：

```ts
inspect(descriptor): PackageStatus
install(descriptor, source): InstallProgress
repair(packageId): InstallProgress
prepareLaunch(ticket): PreparedLocalMap
remove(packageId): void
prune(quota): PruneResult
```

它内部负责签名验证、清单验证、断点下载、hash 校验、原子提交、去重、引用计数、配额和损坏修复。页面只消费状态，不自行枚举 Blob 或拼接文件路径。

`PackageStatus` 至少包含：`not-installed`、`downloading`、`verifying`、`ready`、`outdated`、`incomplete`、`corrupt`、`signature-invalid`、`insufficient-storage`。

### 4.2 启动器 `LocalMapResourceProtocol`

启动器 WebView 注册受控协议，例如：

```text
boxplay://<launch-session-id>/block/<hash>
boxplay://<launch-session-id>/engine/m/<hash>
```

它只接受 `PreparedLocalMap` 允许的 hash，并以内容库中的只读 Blob 返回响应。它不暴露真实文件路径、目录列表或任意 `file://` 访问。启动会话结束后，协议授权立即失效。

协议响应必须具备普通 HTTP 静态资源等价能力：正确的 MIME 类型、`Content-Length`、`Accept-Ranges`/`Range` 请求、错误状态和 WebView 所需的 CORS/CSP 策略。模型加载器、音频播放和大文件分段读取不能因为资源改到本地协议而退化。

### 4.3 资源基址切换

现有游戏资源通常请求：

```text
/runtime/play/<accessId>/block/<hash>
/runtime/play/<accessId>/engine/m/<hash>
```

本地包模式必须在创建游戏会话时由启动票据或会话配置显式声明资源源，而不是依赖 WebView 猜测。例如：

```json
{
  "assetMode": "launcher-local",
  "assetBaseUrl": "boxplay://<launch-session-id>",
  "manifestDigest": "sha256-base64url"
}
```

游戏加载器据此将 `block` 和 `engine/m` 请求映射到本地协议。没有这项协商时，远端网页仍会继续请求反代域名，严格门禁即使通过也不会产生本地加载效果。

这条 seam 把“网页怎样取得本地资源”与“资源存在哪里”隔离开来；普通浏览器仍走现有 HTTPS + Service Worker 路径。

### 4.4 服务器 `MapPackageCatalog`

服务器侧 Module 对启动器提供一个已认证的描述符和下载计划：

```ts
getDescriptor(permanentMapId, releaseVersion?): SignedMapPackageDescriptor
createLaunchTicket(permanentMapId, manifestDigest): LaunchTicket
```

它隐藏发布包目录、私有 Blob、签名私钥和存储实现。调用方只获得公开资源清单、签名、公网/受控下载 URL 与版本兼容结论。

服务器还应提供一个小型启动器引导入口，例如 `GET /api/player-launcher/bootstrap`。启动器用它验证玩家输入的服务器地址，读取服务器名称、登录要求、签名公钥/Key ID 与当前可游玩地图；不要让启动器通过猜测 Play 内部目录或管理 API 来发现地图。

引导入口可在未登录时仅返回服务器名称、登录要求和“是否开放玩家启动器”；地图列表、描述符、下载 URL 与启动票据必须在玩家会话和地图访问授权之后返回。下载 URL 应绑定玩家、地图、`manifestDigest` 和短时有效期，不能作为可长期转发的公开 Blob 地址。

## 5. 描述符与资源清单

建议格式（字段名仅为设计草案）：

```json
{
  "formatVersion": 1,
  "permanentMapId": "4dffa49240b57b50ad2c",
  "accessId": "hahafarm",
  "releaseVersion": "2026.09.27-3",
  "manifestDigest": "sha256-base64url",
  "required": [
    {
      "hash": "Qm...",
      "kind": "terrain|model|texture|image|audio|ui-data|client-script",
      "size": 123456,
      "contentType": "model/gltf-binary"
    }
  ],
  "optional": [],
  "signature": {
    "algorithm": "ES256",
    "publicKey": { "kty": "EC" },
    "value": "base64url-signature"
  }
}
```

### 资源分类

| 分类                                  | 是否可进本地包 | 说明                                                              |
| ------------------------------------- | -------------- | ----------------------------------------------------------------- |
| 地形、地图公开数据                    | 是             | 必须在发布时冻结为内容寻址 Blob                                   |
| 模型、贴图、图片、音频、UI 静态数据   | 是             | 通常为`required`                                                |
| 客户端脚本                            | 后续阶段可支持 | 必须在清单中显式标为`client-script`、签名校验且在浏览器沙箱运行 |
| 服务端脚本                            | 否             | 永远留在服务器运行时                                              |
| 权限、协作者、版本控制、发布控制 Blob | 否             | 与现有`private-blobs.json` 边界一致                             |
| 账号、会话、聊天、实体同步、存档      | 否             | 始终由联机服务器提供                                              |

不能通过文件后缀推断分类。发布阶段必须生成显式、签名的 allowlist；`private-blobs.json` 继续作为“绝不公开”的硬拒绝列表。

## 6. 本地存储布局

建议内容寻址布局：

```text
<launcher-data>/map-packages/
  blobs/<hash>                         # 全局去重的只读内容
  packages/<permanentMapId>/<digest>/
    descriptor.json
    verified.json
    required-hashes.json
  downloads/<digest>/                  # 可恢复的临时下载，不视为已安装
  index.sqlite                          # 包状态、Blob 大小、引用计数、最近使用时间
```

- Blob 下载到临时文件，完成 hash 校验后原子 rename 到 `blobs/<hash>`；
- `verified.json` 只在所有 `required` Blob 校验完成后写入；
- 删除地图包只减少引用计数；引用为零的 Blob 由清理任务回收；
- 清理不删除正在启动、正在下载或被当前启动票据引用的资源；
- 启动器必须在下载前估算新增空间，空间不足时明确拒绝，不进行半隐式淘汰。

## 7. 安装、更新与启动流程

### 7.1 安装/修复

```text
选择地图版本
  → 获取服务器签名描述符
  → 验证描述符签名、格式、资源大小上限与 private hash 拒绝列表
  → 计算本地缺失的 required hash
  → 断点下载缺失 Blob
  → 对每个 Blob 做内容 hash 校验
  → 原子写入 verified.json
  → 状态变为 ready
```

下载源可以是服务器提供的 HTTPS URL、离线资源包或管理员分发介质；无论来源如何，最终都必须通过同一份服务器签名描述符和内容 hash 校验。普通玩家不应信任未签名的任意 `.boxplay` 文件。

在线导入时，玩家输入服务器地址后，启动器自动完成“发现地图 → 选择地图 → 下载差异资源 → 联机启动”。本地导入时，启动器扫描资源包内的描述符，展示其中的地图名称和服务器归属；导入成功后不要求玩家再执行单独的“安装”或“更新”动作。

在线导入的前提是服务器已开启“玩家启动器资源访问”。本地资源包只可预置经签名的公开资源；它不授予地图访问权，玩家仍必须向已开启该功能的服务器完成登录、地图授权和启动票据校验。

### 7.2 严格启动门禁

```text
点击“启动并联机”
  → 获取当前服务器地图描述符/启动票据
  → 本地包的 map ID、版本、digest 必须完全匹配
  → 所有 required Blob 必须再次快速确认存在
  → 缺失/损坏/旧版本：启动器自动下载差异 Blob 并校验
  → 自动补齐期间：显示“正在更新地图资源”，暂不进入地图
  → 校验完成：原子提交为 ready，不需要玩家手动点击修复
  → 完整：创建受限本地资源协议会话
  → 启动 WebView，静态资源基址指向 box3-map:// 会话
  → 使用启动票据连接游戏服务器
```

缺失一个必需资源时，启动器应自动获取该资源、校验后继续启动；玩家不需要手动更新本地资源包。服务器发布新版本时，启动器在下次点击“开始游玩”时自动下载差异资源并启动，不把“更新地图”作为玩家必须理解或确认的流程。下载失败、空间不足、签名无效或网络不可用时才停留在错误状态，并用玩家语言说明“无法准备地图”，而不是暴露 hash、Blob 或版本字段。游戏 WebView 本身不得在已经启动后偷偷从远端 Blob 路径补关键资源；所有自动补齐必须发生在启动器的预检阶段。

### 7.3 联机握手

客户端连接请求带上：

```json
{
  "permanentMapId": "...",
  "releaseVersion": "...",
  "manifestDigest": "...",
  "launchTicket": "..."
}
```

服务器验证票据及三元组一致性。服务器发布新版本后，旧版本客户端显示“需要更新地图资源包”，而不是带着旧资源进入同一个房间。该校验防止视觉资源、UI 数据、客户端脚本与服务器地图版本混用。

服务器不把客户端报告“资源已在本地”当作安全证明：恶意客户端可以伪造该声明或自行选择资源源。启动器负责本机资源完整性门禁；服务器只负责玩家授权、启动票据和发布版本一致性，不能把本地包状态作为反作弊、权限或付费判断依据。

## 8. 反向代理、浏览器与网络边界

本地包模式不能要求远端网页直接读取 `localhost` 或磁盘文件：现代浏览器会受到跨域、混合内容、私网访问策略和用户隐私保护限制。

因此首选架构是启动器承载游戏 WebView，并由启动器提供受限 `boxplay://` 协议；服务器域名和反向代理只承载登录、启动票据、WebSocket 与权威 API。反向代理仍必须正确转发 WebSocket 的 `Upgrade` / `Connection` 头，但它不参与本地静态资源读取。

普通浏览器访问域名时，继续使用现有 HTTPS 路径和 Service Worker 缓存；不能把“严格本地包”误标为已启用。

## 9. 动态资源与客户端脚本

严格模式不允许未知资源在运行时临时下载。发布流水线必须处理三类资源：

1. **发布时已知**：纳入 `required`；
2. **可选且不影响进入**：纳入 `optional`，允许后续显式下载；
3. **运行时派生但影响运行**：发布前预生成并写入新版本，或禁止该地图使用严格模式。

客户端脚本是单独的后续里程碑。当前脚本经 WebSocket 下发，Service Worker 无法缓存。若纳入本地包，服务器应只下发脚本 hash/版本，启动器协议提供已签名客户端脚本；服务端脚本绝不下发。不能在未解决脚本版本握手前声称“完全离线资源启动”。

## 10. 安全与滥用防护

- 描述符签名覆盖地图 ID、版本、清单 digest、资源 hash、大小与分类；
- 启动器对每个 Blob 校验 hash，不能只相信下载 URL、ETag 或文件名；
- 本地协议只服务当前启动票据匹配的 allowlist，拒绝目录遍历、跨地图 hash 和任意文件访问；
- 本地协议仅向启动器承载的 WebView 暴露；普通浏览器、远端页面和任意 localhost 页面不能枚举或读取本地内容库；
- 下载 URL 使用 HTTPS，票据短时有效；内容 hash 即使泄露也不授予地图、玩家或管理权限；
- 对单包大小、单资源大小、资源数和解压比设上限，防止磁盘耗尽与压缩炸弹；
- 管理员导入包时继续执行现有 `.boxplay` 审查；玩家启动器只消费服务器认可的公开描述符；
- 启动器日志不得记录 Token、完整 Cookie、私有资源路径或服务端脚本内容。

## 11. UX 设计

默认地图页只显示地图封面、名称、在线状态与“开始游玩”。版本、digest、资源数和占用仅放在“详情/诊断”中，普通玩家不需要处理更新。

地图卡片内部状态：

| 状态         | 行为                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| 未安装       | 点击“开始游玩”后自动下载；显示准备进度                                   |
| 下载中       | 显示“正在准备地图”和总进度；默认不要求玩家选择文件或版本                 |
| 已安装       | 直接显示“开始游玩”                                                       |
| 有更新       | 点击启动后自动下载差异资源，完成后自动进入                                 |
| 损坏/不完整  | 启动时自动修复；仅在失败时显示“重试”                                     |
| 服务器不可用 | 已安装地图可显示，但“联机启动”不可用；是否支持离线单机由地图能力另行声明 |

设置页提供总配额、每包大小、清理未使用版本、验证全部资源和导入受签名离线包。删除操作必须说明会删除哪些地图版本，且不删除仍被其它地图引用的 Blob。

## 12. 分阶段实施

### 阶段 A：发布描述符与只读检查

- 发布端生成公开资源描述符、digest 和签名；
- 增加受服务器级开关、玩家会话和地图授权保护的启动器引导入口，支持在线服务器发现和已签名本地资源包导入；
- 启动器只展示可游玩地图和内部完整性状态；
- 不改变游戏资源加载路径；
- 验收：损坏、私有 hash、错误签名、版本冲突均被拒绝。

### 阶段 B：下载器与内容库

- 实现 `LocalMapPackageManager`、去重、断点续传、配额、修复与删除；
- 支持导入服务器签名的本地资源包；
- 验收：断网恢复、重复 Blob 去重、磁盘不足、并发安装、原子提交。

### 阶段 C：启动器 WebView 本地协议

- 实现 `LocalMapResourceProtocol`；
- 在会话/启动票据中协商 `assetMode`、`assetBaseUrl` 和 `manifestDigest`，使 WebView 使用本地协议加载已验证静态资源；
- 服务器保持现有联机与 WebSocket 流程；
- 验收：抓包确认 required 静态资源不再由游戏页面请求远端；Range 音频与模型加载正常；删掉任意 Blob 后启动器自动补齐、校验并进入。

### 阶段 D：版本握手与强制更新

- 增加启动票据中的地图版本/digest；
- 服务器拒绝版本不一致的连接；
- 验收：服务器发布新版本后，旧包不能进入；更新完成后可进入。

### 阶段 E：客户端脚本与派生资源

- 仅在签名、沙箱、版本协议和发布确定性全部完成后纳入；
- 验收：客户端脚本版本与 UI/资源版本一致；服务端脚本永不进入本地包。

## 13. 验收矩阵

| 场景                       | 预期                                                         |
| -------------------------- | ------------------------------------------------------------ |
| 在线导入，全新机器         | 输入服务器地址、选择地图；点击启动后自动下载、校验完成再进入 |
| 服务器未开启启动器资源访问 | 不列出地图、不下载资源，显示服务器未开放提示                 |
| 玩家无地图访问权           | 不返回该地图描述符、下载 URL 或启动票据                      |
| 本地导入资源包             | 验证签名后写入本地内容库；连接对应服务器时自动复用           |
| 完整包，网络慢             | 静态资源本地读取；联机只走实时连接                           |
| 缺一个 1KB Blob            | 启动器自动补齐、校验后进入；游戏内不补齐                     |
| Blob 被篡改                | hash 校验失败，禁止启动                                      |
| 描述符签名错误             | 不显示为可安装版本                                           |
| 两地图共享同一模型         | 本地仅一份 Blob，删除一个包不删除 Blob                       |
| 服务器发布新版本           | 提示更新；旧 digest 不能联机                                 |
| 反向代理/WebSocket 正常    | 联机正常，且不影响本地资源协议                               |
| 反向代理上游版本混用       | 版本握手拒绝进入并提示服务器版本不一致                       |
| 普通浏览器打开域名         | 不获得本机包访问权限；继续走网页缓存策略                     |

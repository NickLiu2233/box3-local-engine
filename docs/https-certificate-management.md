# Nginx 与公网证书配置

当前源码 v0.3.0，更新日期 2026-10-09。Nginx 来源位于“数据配置 → 数据服务”，公网地址和证书位于“访问设置”。源码更新不代表已安装 App 或运行容器已更新。

## Nginx 来源

- **内置 Nginx（默认）**：使用 `docker.m.daocloud.io/library/nginx:stable-bookworm`，支持“立即下载”和“启用并启动”，显示实际镜像版本。默认选中不等于已经下载或启动。
- **已有外部 Nginx**：连接管理端所在机器安装的 Nginx。自动检测版本、可执行文件和默认主配置；重新点击选项可再次检测。检测只读取状态，保存时才写入本实例片段并重载。

已明确保存的外部选择会保留。没有来源记录或旧 `disabled` 状态时使用内置选项。切换选项即时更新界面，保存或下载、启用时才持久化；切换到外部模式前需确认停止运行中的内置入口。

## 公网地址模式

独立地址模式逐服务填写，留空的服务不继承其他服务地址。共用地址模式填写一个 IP 或域名，各服务通过端口或路径区分。切换模式保留两套草稿，独立模式不应用共用路径草稿。

| 场景 | 示例 | 生成规则 |
| --- | --- | --- |
| 独立域名 | `play.example.com` | 有证书用 HTTPS，否则 HTTP；域名默认 443/80 |
| 独立 IP | `203.0.113.10` | 自动判断协议，未指定端口时使用服务端口 |
| 显式协议和端口 | `http://play.example.com:8080` | 显式协议与端口优先 |
| 共用地址，路径为空 | `example.com` | 各服务使用配置的服务端口，如 3121、3127 |
| 共用地址，配置路径 | `example.com` + `/play` | 使用共用地址端口，未写端口时为 443/80 |

例如共用地址 `https://example.com`：Play 路径留空得到 `https://example.com:3121`，Creator 路径 `/arena` 得到 `https://example.com/arena`。路径非空时保留共用地址的显式端口；路径为空时使用各服务端口。

路径去除首尾斜线后最多 128 个 ASCII 字符，仅允许字母、数字、下划线、短横线和分隔斜线。首段不能为 `api`、`_next`、`runtime`、`p` 或 `player-admin`。共用地址不能携带路径，在各服务路径字段填写。

不同路径可在同一地址和端口分流，不同域名可通过 server_name 共用端口。相同域名、端口和路径不能重复占用，同一监听端口不能混用 HTTP 与 HTTPS。HTTPS 支持自定义端口。DNS、防火墙及证书覆盖范围由部署者配置。

路径入口要求服务镜像包含 `box.routing.base-path=runtime-v1` 标签；旧镜像或缺少能力的自定义登录镜像在应用前会被拒绝。

## 证书和保存流程

1. 填写地址，按需配置共用或独立证书。SSL 区域默认折叠，显示已配置、即将到期或已过期状态。
2. 导入 PEM 证书（.pem/.crt/.cer，最大 256 KiB）与未加密私钥（.key/.pem，最大 64 KiB）。选择时检查结构，保存时由 OpenSSL 校验匹配、域名和有效期。
3. 未重新选择文件时复用已保存证书。裸地址根据完整的新文件或已保存证书选择 HTTPS；显式 `http://` 保留 HTTP。HTTP 路由也可由 Nginx 代理，无需证书。
4. 保存时先持久化地址，再校验并应用入口。内置入口接管公网监听端口，上游容器取消对应端口映射；本机外部入口使用独立 loopback 上游端口。需要变更时仅重建本项目已经运行的相关服务。
5. 应用失败时恢复或保留旧入口、证书及上游运行配置。地址保存与入口应用不是一个数据库事务；出现“配置已保存，但后续应用失败”时检查错误并重新应用。

裸地址草稿和完整地址分别保存，自动判断不会永久写死草稿协议。清除共用证书会停用使用它的 HTTPS 路由，保留无关 HTTP 路由及其他证书；下次保存时，无证书的裸地址按 HTTP 重新生成。

## 本机外部 Nginx

通过 PATH、Homebrew 和常见 Unix 路径寻找 Nginx，读取 `nginx -V` 中的默认主配置。要求支持 `x509 -checkhost` 的 OpenSSL，macOS 优先使用 Homebrew OpenSSL 3。

未安装时可以保存证书及待应用状态，安装并启动后再次保存。自动接入支持默认主配置启动方式，不支持自定义 -c/-p 或远程 Nginx。容器内管理端不能自动修改宿主机系统 Nginx，应使用内置入口或在目标机器直接运行管理端。

片段位于数据目录 `https/local-nginx.conf`，主配置顶层 http 块只加入本实例 include。管理端需要文件写入及重载权限，不自动执行 sudo。更新前检查原配置，写入后执行 nginx -t，通过后重载；失败恢复原配置，回退失败会明确提示。

## 安全与运行边界

私钥不回显，不进入 .env、页面、导出配置或浏览器存储。临时内容只保留在内存，离开访问设置后清除。证书版本位于 `https/revisions/`，Unix 文件权限 0600、目录 0700，Windows 继承数据目录权限。普通工程备份不含证书，迁移时单独备份。

内置容器通过所有权标签隔离实例，配置应用前执行 nginx -t。支持 TLS 1.2/1.3、Host、协议头和 WebSocket Upgrade。没有 ACME 签发、自动续期或自动 HTTP 重定向。Nginx 镜像不包含在六服务离线归档中，首次下载需要网络。

## 管理命令

桌面使用 Tauri，Web 使用认证后的 `POST /api/commands/{name}`。

| 命令 | 用途 |
| --- | --- |
| `get_ssl_status` | 来源、镜像、运行状态、证书公开元数据及导出配置 |
| `set_nginx_provider` | 保存 managed/external；disabled 兼容旧调用 |
| `install_nginx_image` | 下载或复用官方稳定版镜像 |
| `apply_ssl_config` | 应用 HTTP/HTTPS 路由与证书，兼容旧单证书格式 |
| `stop_ssl_proxy` | 停止本实例内置入口，保留配置与证书 |
| `export_ssl_configuration` | 导出配置，不能视为已部署 |
| `verify_ssl_endpoint` | TLS 探测，不等同于真实登录和 WSS 会话验收 |

工程入口及检查见[公网路由工程说明](./public-routing-engineering.md)。日期命名的 Nginx 文档记录历史方案，当前操作以本文为准。

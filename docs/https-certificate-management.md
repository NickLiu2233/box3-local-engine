# Nginx 与公网证书配置

源码版本：v0.3.0；2026-10-08 调整配置入口。Nginx 放在“数据配置 → 数据服务”，各服务的地址和证书放在“访问设置 → 公网”各服务卡片中；不再提供共用公网地址或共用 SSL 配置。源代码更新不代表现有安装包或运行容器已自动更新。

## 使用方式

数据服务中选择 Nginx 来源：

- **内置 Nginx**：默认下载官方最新稳定版 `docker.m.daocloud.io/library/nginx:stable-bookworm`，也可直接使用本机已有的该镜像。界面读取镜像实际版本号，使用与 Redis 一致的“立即下载”和“启用并启动”入口。下载和启动时复用 Redis 的处理中弹窗，完成显示成功提示、失败显示错误。首次启用会引导填写 HTTPS 地址并导入证书，保存后启动；已有证书配置则直接启动。
- **已有外部 Nginx（默认）**：当前界面连接本机系统安装的 Nginx，不要求是镜像。首次进入配置页或选择外部卡片时自动检测安装状态；下方显示检测中、未安装、检测失败或已安装状态，已安装时展示版本号、可执行文件路径和主配置文件路径，可复制路径。重新点击已选中的外部卡片会再次检测。检测仅运行 `nginx -V` 和读取路径，不修改配置、不要求先保存选择，也不把已安装当作正在运行。管理端使用 OpenSSL 校验证书，保存时自动接入主配置、执行校验并重载。没有安装 Nginx 时仍可默认选择外部模式。卡片切换与 Redis 一样即时更新选中样式，不请求后台、不变灰；保存配置或下载、启动时才持久化选择。保存外部模式时可确认停止运行中的内置入口。移除手动“刷新状态”按钮，保留页面加载和操作完成后的自动状态更新。

外部模式要求管理端安装支持 `x509 -checkhost` 的 OpenSSL；macOS 优先使用 Homebrew 的 OpenSSL 3。此模式不会为证书校验下载或运行 Nginx 镜像。

## 地址与证书

1. 分别填写各服务的公网地址，填写 `https://`、域名以及需要的入口端口。
2. 公网设置中，各服务都提供 SSL 证书入口，不依赖地址是否已填写。默认折叠，标题在已保存证书时显示“已配置”，30 天内到期追加黄色“即将到期”，过期追加红色“已过期”；正常证书不追加到期警告。点击“SSL 证书”展开，标题、有效期提示与文件选择之间保持 12px 间距。选择证书文件（`.pem` / `.crt` / `.cer`）和证书密钥文件（`.key` / `.pem`），内容须为 PEM 格式，密钥不能加密。选择时检查后缀、大小和 PEM 内容结构；保存时再由 OpenSSL 检查证书、密钥匹配、域名和有效期。证书上限 256 KiB，私钥上限 64 KiB。
3. 每个服务单独选择证书和私钥，更新一个服务不会给其他服务复制证书。未重新选择文件时复用该服务已经保存的证书，并再次校验域名、有效期及私钥。旧版已保存的证书仍兼容读取，但界面不再提供共用证书选择或提交入口。
4. 点击原有“保存配置”。公网地址保存后，同时应用所选证书；内置 Nginx 自动校验并更新配置，无需单独导出。已有证书在地址或 Nginx 来源变更时复用并重新应用；本机外部模式自动写入专用配置片段、执行 `nginx -t` 并重载。若证书应用失败，显示“配置已保存，但后续应用失败”，托管入口恢复或保留旧证书配置。
5. 重新启动相关引擎服务，使运行时生成的链接使用新地址。证书更新本身不会自动重启引擎服务。

地址不重复输入，也不会在证书应用时另行覆盖公网地址。只有各服务明确填写的 HTTPS 地址进入证书配置，HTTP 地址不代理；未填写地址的服务不在界面生成公网链接，也不再从旧共用域名继承 URL。保存后的显式空地址在运行时保留为本机 HTTP 地址。

界面的 HTTPS 入口统一使用 **443**，不再自动分配 13121 等高端口。多个服务需使用不同独立域名，由 Nginx 的 `server_name` 在同一 443 监听上区分；请在各服务已有的“独立公网地址”中填写 `https://<域名>`。域名的 DNS 需指向该服务器，各服务的证书必须覆盖相应域名。多个服务填写同一 HTTPS 域名会在保存前明确提示，避免同一域名／端口无法区分服务。

界面会在保存前拒绝重复 HTTPS 域名及非 443 的显式 HTTPS 端口，保留尚未保存的表单与证书选择。引擎原 HTTP 端口继续用于上游，Nginx 监听 443，应用链接、登录链接和 CORS 使用对应的独立 HTTPS 域名。旧 API 自定义端口仍可读取，但界面保存和启用采用新 443 规则。若已运行旧端口集合的内置入口，改变监听集合前需先停用旧入口。


## 本机外部 Nginx

界面已移除单独的“证书配置／导出 Nginx 配置”面板，直接使用“保存配置”。本机 Nginx 必须已经安装并启动；尚未安装时仍可选择外部模式；保存时校验证书并持久化地址、证书和待应用状态，显示“需要安装并启动本机 Nginx 才能启用 SSL”的提醒，不阻止保存。安装并启动后再次保存即可复用已保存证书并自动应用。SSL 证书区域会持续显示待应用提醒。

管理端通过 PATH 以及 Homebrew、常见 Unix 安装位置查找 Nginx，读取 `nginx -V` 中的默认主配置路径。适用于按默认主配置运行的 Nginx；自定义 `-c` 或 `-p` 启动方式尚未支持。主配置必须包含顶层 `http` 块，管理端用户需要具有配置文件和数据目录的写入权限，以及重载 Nginx 的权限。权限不足会报错，不自动执行 sudo。

配置片段写入引擎数据目录 `https/local-nginx.conf`，主配置的 `http` 块只加入本实例片段的 `include`，已有服务配置保持原样，重复保存不会重复加入。证书引用真实本机数据目录中的版本文件，路径带空格时使用引号；上游使用 `127.0.0.1` 和现有引擎端口。每个实例使用独立的 WebSocket 连接变量。

更新前检查原配置，写入后再次运行 `nginx -t -c <主配置>`，通过后执行 `nginx -s reload -c <主配置>`。校验或重载失败会恢复原主配置和原片段；必要时重载旧配置。若回退也失败，会明确提示并保留可能仍被运行进程引用的证书版本。

容器内 Web 管理端无法自动修改宿主机的系统 Nginx，需将管理端直接运行在目标机器上。远程 Nginx 或自定义部署仍可通过旧管理命令使用 `externalLocal: false` 校验证书及生成配置；这不代表已自动部署到远程机器。保留 `get_ssl_status` 的 `config.externalConfig` 与桌面 `export_ssl_configuration` 命令以兼容旧调用方。

## 安全与运行边界

私钥不回显、不写入安装配置、导出文本或浏览器本地存储。文件只暂存内存；离开访问设置会清除临时文件内容。已保存文件在引擎数据目录 `https/revisions/` 中，Unix 文件权限为 0600、证书目录为 0700；Windows 继承数据目录的用户访问权限。普通工程备份不包含证书，迁移前应单独备份并停止托管入口。

托管 Nginx 使用专属所有权标签，只操作本实例容器；应用前执行 `nginx -t`，失败保留或恢复旧配置。若回退失败会明确报错并保留可能仍使用的证书版本。状态读取会显示镜像是否已下载及托管入口状态，不把外部 Nginx 当成 Docker 容器。

内置与本机外部 Nginx 支持 TLS 1.2/1.3、Host/协议头和 WebSocket Upgrade；HTTPS 地址对应 WSS。到期日期在各服务证书区域显示，30 天内提示更换。状态在页面加载及操作完成后自动更新，不新增周期轮询。有效期卡片支持窄宽度换行，30 天内到期显示黄色，已过期显示红色，并分别标注状态；右侧删除图标移除该服务证书、私钥与 HTTPS 路由，保留其他服务。删除后重新选择该服务证书和私钥并保存，才恢复它的 HTTPS 路由。不提供 ACME 签发、自动续期或自动 HTTP 重定向。Nginx 镜像不包含在现有六服务离线归档中。

## 管理命令

桌面使用 Tauri，Web 管理端沿用认证后的 `POST /api/commands/{name}`。

| 命令 | 用途 |
| --- | --- |
| `get_ssl_status` | 读取 Nginx 来源、镜像是否可用、托管入口状态、各证书公开元数据及导出配置 |
| `set_nginx_provider` | 保存 disabled / managed / external 来源；切换前先停止托管入口 |
| `install_nginx_image` | 单独准备官方 Nginx 镜像，已有镜像时直接复用 |
| `apply_ssl_config` | 以已有地址生成 routes，按服务传入 certificates 或复用已保存证书；externalLocal=true 时更新本机外部 Nginx，默认 false 兼容旧导出调用；兼容旧单证书格式 |
| `stop_ssl_proxy` | 停止本实例托管入口并保留证书 |
| `export_ssl_configuration` | 桌面保存配置；Web 从认证状态响应中的配置文本导出 |
| `verify_ssl_endpoint` | 保留的 TLS 探测命令，按各路由实际端口检查；不代表已登录 WSS 会话验收 |

## 验证范围

改造回归覆盖现有公网地址优先级、证书随保存提交、共用与独立证书、旧单证书兼容、私钥不进入安装配置及页面、不同监听端口、失败回退和外部模式无可用 Docker 时的真实 OpenSSL 校验。另用临时证书和隔离 Docker 网络验证 HTTPS、受信任 TLS、WSS echo、错误私钥保留旧入口、按服务证书更新及外部配置导出。

这不等于公网 DNS、防火墙、多玩家、真实远程 Nginx 或 Windows 原生界面的现场验收。

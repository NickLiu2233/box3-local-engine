# BOX3 Engine 私服方案对比

## 私服是什么

私服是由学校、工作室、企业或社区自行部署和运营的 BOX3 Engine 服务。服主自行决定服务器地址、创作者、玩家、地图和运营规则；引擎提供 Creator、VOXA、Play、玩家账号和部署工具，但不替服主经营社区或托管用户数据。

## 私服的优势

| 优势           | 对业务的意义                                                                         |
| -------------- | ------------------------------------------------------------------------------------ |
| 数据与账号自主 | 地图、玩家、脚本存档和审计数据由服主保管，可自行备份、迁移和制定保留周期。           |
| 运营规则自主   | 可自行决定开放时间、访问范围、创作者权限、地图上架与下架，不受统一平台运营策略影响。 |
| 部署位置可选   | 可部署在本机、校园/企业内网、私有云或公网服务器，适配教学、内部协作和品牌活动。      |
| 长期可控       | 正常创作与游玩不依赖在线资源域名；即使不接入外部平台，已部署的服务仍可独立运行。     |
| 品牌与体验独立 | 可使用自己的域名、入口和内容运营方式，适合做独立社区、课程项目或企业互动空间。       |
| 成本结构清晰   | 基础设施费用由服主直接掌握；规模小可低成本运行，规模扩大时可按实际需求扩容。         |

## 私服的劣势与责任

| 代价                 | 需要承担的事项                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------- |
| 要有运维能力         | 需要准备 Docker、PostgreSQL、备份、升级、监控和故障恢复；桌面启动器降低门槛，但不能代替运维。 |
| 安全责任在服主       | 公网部署要自行配置 HTTPS、访问控制、强密钥、防火墙和数据库保护。                              |
| 内容与用户责任在服主 | 服主负责地图内容、用户行为、投诉处理、未成年人保护及适用的经营和数据合规要求。                |
| 没有统一流量入口     | 私服需要自行拉新、运营社群和维护玩家关系，不能天然获得在线平台的用户分发。                    |
| 升级需要自行安排     | 服主应在备份后测试升级，并决定何时采用新版本。                                                |

## 与在线托管平台的对比

| 维度       | BOX3 Engine 私服                                                   | 在线托管平台                               |
| ---------- | ------------------------------------------------------------------ | ------------------------------------------ |
| 服务与数据 | 由服主掌握，部署位置和备份策略可选                                 | 由平台托管，部署、备份和基础运维更省心     |
| 上线速度   | 需先完成部署与配置                                                 | 注册后通常可直接使用，适合快速试用         |
| 运营自由度 | 可定义访问、权限、内容和品牌规则                                   | 需遵循平台功能边界与运营规则               |
| 稳定性责任 | 服主负责容量、故障和安全                                           | 平台负责基础设施可用性与日常运维           |
| 成本模式   | 自行承担服务器和运维成本，规模可控                                 | 通常以平台服务规则和资源方案为准           |
| 适合场景   | 内网教学、私有社区、企业活动、独立品牌运营、需要自主数据管理的项目 | 个人试用、快速上线、没有运维资源的轻量项目 |

## 结论

私服的核心价值不是“免费服务器”，而是**数据、运营和品牌的自主权**。它适合有明确私有化需求、愿意承担基础运维责任的组织；在线托管则适合希望马上开始、优先降低运维负担的用户。两者可并存：在线平台承担低门槛体验，私服满足长期运营和私有化部署。

# BOX3 Engine 图形化部署管理器

图形化部署管理器（桌面程序名称为 **BOX3 Engine**）是 Windows、macOS 和 Linux 桌面服主的安装、配置和日常运维工具。它通过 Docker 管理五个 BOX3 Engine 业务镜像：Creator、Play、VOXA、Player Service 和参考登录门户。

它不安装、升级、启动或删除 PostgreSQL/Redis。当前版本要求服主提供可访问的 PostgreSQL；Redis 可留空。

## 开始前准备

1. 安装 Docker Desktop（Windows/macOS）或 Docker Engine + Compose（Linux 桌面）。Docker 必须能运行 Linux 容器。
2. 准备一个 PostgreSQL 数据库，确认电脑能够连到其主机与端口。
3. 下载与当前电脑 CPU 架构相符的离线包并解压。
4. 启动程序：Windows 打开 `box-local-engine-manager.exe`，macOS 打开 `BOX3 Engine.app`，Linux 运行包内 `box-local-engine-manager`。

首次保存配置时，启动器会检查 PostgreSQL 连通性、端口冲突、访问地址和密钥；不会自动启动业务容器。

## 配置流程

### 1. 数据服务

在“数据配置 → 数据服务”填写：

- PostgreSQL 地址、端口、数据库名、账号、密码与 SSL 选项；全部必填。
- Redis 地址、端口、密码和 DB 编号；完全可选。清空 Redis 地址即可关闭 Redis。

启动器保存分开的数据库字段，不把明文 `BOX_DATABASE_URL` 留在服主 `.env`；它会在 `.runtime.env` 中生成经过 URL 编码的连接串。数据库密码留空时会保留已经保存的密码，首次保存则必须填写。

### 2. 访问设置

访问模式决定 Play、玩家服务和参考登录门户的访问地址：

- **本机**：仅此电脑访问，使用 `127.0.0.1`。
- **局域网**：使用检测到的私网 IP；其他设备用该 IP 和端口访问。
- **公网**：填写公网 IP。实际生产应让公网 IP/域名由 HTTPS 反向代理承接，避免直接把 Docker 端口暴露到互联网。

Creator 与 VOXA 有独立的访问地址，并被强制限制为本机或私网 IP。不能使用公网 IP、域名或 `0.0.0.0` 让它们对互联网提供服务。这个限制由启动器后端在保存与启动前都执行，手改原始 `.env` 也不能绕过。

每项服务都有独立端口，且五个端口不能重复。端口变化后，启动器会重新派生 Creator、VOXA、Play、登录门户之间的 URL 和 CORS 白名单，不需要服主逐项计算。

### 3. 运行容量与备份

容量页控制 Creator 编辑/预览与 Play 同时运行的地图数量，不是玩家总数。大型地图或内存较小的电脑应从默认值开始，观察“性能监控”后再调整。

地图备份默认关闭。启用后会按间隔导出可编辑工程；可设置间隔、每地图保留份数和最长保留天数。备份不包含 PostgreSQL、Redis 或玩家账号，所以数据库仍需由数据库提供方单独备份。

### 4. 服主与安全

首次保存时会生成下列密钥；建议保持自动生成的不同随机值：

- `PERMISSION_TOKEN_SECRET`
- `BOX_PLAYER_AUTH_API_KEY`
- `BOX_PLAY_ADMIN_TOKEN`

“查看密钥”只在当前本机窗口临时显示。不要截图、复制到聊天、提交到仓库或输入到玩家前端。详细变量说明见[配置参考](./configuration-reference.md)。

### 5. 原始 `.env`

高级使用者可查看和修改启动器维护的原始 `.env`。保存时会验证变量名、端口与 Creator 网络策略，并自动删除由启动器负责生成的派生项。不要手工维护 `.runtime.env`；它会被重写。

## 启动范围

服务总览的“启动”会弹出范围选择：

| 选择     | 启动的服务                                        | 适用场景                   |
| -------- | ------------------------------------------------- | -------------------------- |
| 全部服务 | Creator、VOXA、Play、Player Service、参考登录门户 | 一台机器同时创作和对外游玩 |
| 创作端   | Creator、VOXA、Player Service、参考登录门户       | 创作者编辑、预览、模型制作 |
| 游玩端   | Play、Player Service、参考登录门户                | 只托管已发布地图给玩家     |

服务未运行时不显示“打开”或“复制地址”，避免复制到不可访问的 URL。启动后可以从卡片打开页面、复制访问地址或查看状态。停止操作只停止容器和临时运行时，不删除项目、模型、备份、配置、数据库或 Docker volume。

## 备份与恢复

“数据与备份”管理启动器保存的工程备份：

- **立即备份**：打包当前本地工程数据；
- **导出**：选择位置把备份文件复制出去，便于离线保存或交给可信协作者；
- **导入备份**：先校验归档结构，再复制进备份库；
- **恢复**：会先停止业务服务并要求二次确认，再把备份恢复到本地运行目录；完成后需从服务总览重新启动；
- **删除**：只删除所选备份文件，操作前要求二次确认。

恢复覆盖的是启动器管理的本地工程、模型和配置文件，不会还原远程 PostgreSQL/Redis。恢复前应单独备份数据库，特别是玩家账号和脚本持久数据。

## 离线包、数据位置与升级

| 平台            | 包内结构                                                            | 使用要点                                    |
| --------------- | ------------------------------------------------------------------- | ------------------------------------------- |
| macOS           | ZIP 内只有 `BOX3 Engine.app`；五服务镜像和清单嵌入 App Resources    | 可将 App 移入“应用程序”目录后再首次启动     |
| Windows / Linux | 程序、五服务镜像 `.tar.gz` 与 `BOX-OFFLINE-IMAGE.json` 位于同一目录 | 首次导入前不能拆散、改名或只复制 EXE/二进制 |

启动器在导入镜像前校验归档 SHA-256、镜像标签和目标 Linux 架构。出现“不匹配”通常表示程序和镜像归档不是同一版；请重新解压完整离线包，不要混用两个下载包里的文件。

程序目录可以替换或升级；持久数据保存在系统应用数据目录的 `runtime/` 下。升级前仍建议导出重要地图工程、启动器备份以及 PostgreSQL 数据库备份。

## 参考登录门户与自建门户

离线包默认包含 `player-auth-portal`，用于快速测试玩家注册和登录。它只是参考实现，账号、权限和 Session 都由 Player Service 管理。

服主可以独立部署自己的登录程序，并通过服务端调用 Player Service API。浏览器不能携带 `BOX_PLAYER_AUTH_API_KEY`。当前启动器的“启动范围”仍会启动参考门户；完全替换为自建门户时，应改用 Compose/反向代理自行编排门户，并把 `BOX_PLAYER_LOGIN_URL` 指向自建地址。具体接入和安全要求见[自建登录门户](./self-hosted-login.md)。

## 常见问题

| 现象                      | 先检查                                                                                                 |
| ------------------------- | ------------------------------------------------------------------------------------------------------ |
| 保存配置失败              | PostgreSQL 地址、端口、云安全组/防火墙、账号密码、数据库 SSL 设置；Redis 只有填写后才参与检查          |
| 点击启动后仍显示启动      | 在服务总览刷新状态，随后查看运行日志是否有镜像导入、端口占用或数据库连接错误                           |
| 局域网设备打不开          | 电脑防火墙、所选私网 IP、端口、路由隔离；Creator/VOXA 只能在同一可信网络使用                           |
| Play 页面能打开但无法登录 | Player Service 与登录门户的公开地址是否一致；Cookie 域、HTTPS、反向代理头和 `BOX_TRUST_PROXY` 是否正确 |
| 打不开 App/EXE            | 检查系统架构是否匹配；内部测试包可能未签名，按组织的测试流程确认来源后再处理系统安全提示               |

维护者构建离线包、Tag CI 与签名的流程见[构建、分发与 CI](./release-and-distribution.md)。

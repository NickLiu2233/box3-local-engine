# 作品创建、编辑与发布

创作者日常只使用创作端的作品管理器，不需要手动操作工程文件或分别启动其他程序。

## 打开创作端

在仓库根目录执行：

```bash
pnpm dev
```

然后打开：

```text
http://127.0.0.1:3002/
```

Docker 部署创作端可使用：

```bash
pnpm creator
```

## 创建作品

1. 点击右上角“新建作品”。
2. 填写作品名称。
3. 可继续填写作者、简介、封面、版本号和更新说明。
4. 保存后，作品会出现在作品列表中。

每个作品都有独立工程目录，不会与其他作品共用世界状态。

## 编辑与预览

- 点击“编辑”会在新页面打开该作品的编辑器。
- 点击“游玩”会在新页面打开当前工程预览。
- 编辑器保存或自动保存后，作品管理器会记录最新世界版本。
- 切换作品时，创作端会自动切换内部运行时，不需要手动改端口。

发布前请先在编辑器中保存一次。刚导入的工程也应先打开并保存，再进行发布。

## 编辑作品信息

在作品卡片的更多菜单中选择“编辑信息”，可以维护：

- 作品名称
- 作者
- 简介
- 封面
- 版本号
- 更新说明

这些信息会随可编辑工程包和游玩发布包一起导出，方便其他设备或服主识别作品。

## 换设备继续编辑

在主地图或副地图菜单中点击“导出完整地图组”，会下载：

```text
作品名称_项目ID.boxproject
```

在另一台安装了 Local Engine 的设备上打开作品管理器，点击右上角“导入工程”并选择文件，
随后可选择两种归属方式：

- **作为独立地图组**：导入包内全部成员，保留原来的主地图、副地图关系，并为整组分配新的本地 ID。
- **成为现有地图的副地图**：只导入当初点击“导出完整地图组”的那张地图，并选择一个现有主地图作为归属；导入后的地图使用目标地图组的共享资源库。

两种方式都不会覆盖已有同名作品。

所有 `.boxproject` 都是地图组包；即使地图组当前只有一张主地图，也使用相同格式。从主地图或
任意副地图执行导出都会包含主地图、全部副地图、成员关系、导出入口地图和唯一共享资源根。
独立导入时所有成员会一起创建；作为副地图导入时则使用导出入口地图作为新副地图。地形、
实体仍按地图隔离，UI、图片、音频、项目模型、皮肤和共享脚本仍由最终归属的地图组共享。

本地发行版不读取早期单地图归档结构。该格式从未作为发布格式交付，因此不保留兼容代码。

`.boxproject` 是可编辑工程包，只应交给作者或可信协作者。

### 云端迁移工程的脚本

云端迁移完成后，入口脚本和其他地图脚本都会随工程包保存；它们不是只在运行时临时下载的文件。地图组的共享脚本是另一类资源：共享资源库刷新时只会同步共享脚本，不会覆盖或删除当前地图的普通脚本。

如果编辑器脚本树只显示入口文件、但地图仍能运行，先重新打开工程并确认迁移任务没有报告资源缺失。不要把普通脚本手工复制到共享资源库，也不要删除 blob 目录。此类现象通常是编辑器文件树同步范围错误，应保留工程包并提供地图 ID、迁移报告和 Creator/game-server 日志给维护者。

## 发布作品

1. 确认编辑器已经保存。
2. 在作品菜单中点击“发布”。
3. 填写新版本号和更新说明。
4. 确认发布。

从主地图或任意副地图点击发布，都会发布整个地图组。系统会先确认每张地图已经保存，再为
主地图和全部副地图生成同一版本号的不可变游玩快照；任何一张失败时不会留下半个发布版本。
工程之后继续修改，不会改变已经发布的版本；需要更新时请为整个地图组发布新的版本号。
每张地图的发布清单都会固定同一个地图组身份以及当时的共享 revision。

## 导出游玩部署包

在作品菜单中选择“发布地图组游玩包”。发布成功后会下载一个 `.boxplay` 文件，其中包含
指定版本的主地图、全部副地图及其主副关系。服主只需导入这一个文件，游玩端会一次安装
地图组的全部地图。部署包不包含可编辑的 `source/` 工程、作品管理器或编辑器。

发布窗口只提供两种资源方式：

| 方式           | 适用场景                                           | 资源位置                                                               |
| -------------- | -------------------------------------------------- | ---------------------------------------------------------------------- |
| **仅本地资源** | 需要完整离线交付                                   | 所有运行资源都写入 `.boxplay`，包最大                                  |
| **仅引用 OSS** | 发布者有自己的 S3 兼容 OSS/CDN，且希望玩家最快加载 | `.boxplay` 仅保留私有运行数据；模型、纹理、图片和音频从发布者 CDN 读取 |

选择“仅引用 OSS”时，在同一窗口填写发布者自己的 S3 Endpoint、Bucket、Region、Access Key、
Secret Key 和资源公开地址。配置仅保存于该 Creator 机器的
`apps/local-engine/projects/.asset-distribution.json`，并受 Git 忽略；游玩包只写入公开 CDN
地址和资源 hash，**不会**包含 Endpoint、Bucket 或任何写入凭证。不同开发者导出的不同游玩包
可以使用不同 CDN，服主不需要配置 OSS。

对象存储必须把资源公开为：

```text
https://你的-CDN/engine/m/<内容-hash>
```

并允许 Play 网页跨域读取（CORS）。内容 hash 是不可变地址，上传后不要删除或用其他文件覆盖；
否则所有引用该资源的游玩包都会失效。Play 导入引用型包时会验证地址格式，运行时只会从该包
清单中允许的 hash 回源，并校验下载内容是否与 hash 匹配。

创作端不会构建游玩镜像。第一次导出包含 `play-image.tar` 的部署包前，先在仓库根目录执行：

```bash
pnpm play
pnpm creator:up
```

第一条命令只准备并启动游玩端镜像；第二条命令使用已有镜像返回创作端。之后只要游玩镜像
版本没有变化，就不需要重复构建。默认镜像架构为 `linux/amd64`；目标服主是 ARM 服务器时，
应先设置 `BOX_PLAY_PLATFORM=linux/arm64`，再执行 `pnpm play`。

服主进入部署包目录后执行：

```bash
docker load -i play-image.tar
docker compose up -d
```

玩家只需打开：

```text
http://服务器地址:3000/
```

网页、资源和多人连接都走这一个地址，不需要再开放第二个游戏端口。

## 删除作品

删除操作会先显示项目内确认弹窗。确认后会删除本机的可编辑工程和该工程保存的发布版本。
重要作品请先导出 `.boxproject` 备份。

## 恢复历史版本

Local Engine 会在打开、导出和发布工程时自动保存有效快照，最多保留最近 5 份。在作品卡片
的更多菜单中选择“恢复历史版本”，可以查看快照产生时间、原因和大小，并恢复指定版本。

恢复前会先保护当前有效工程，因此误恢复后仍可从恢复记录切回。已经打开的编辑器不会被
强制刷新；恢复完成后请关闭旧编辑页并重新打开工程。

## 工程与发布包的区别

| 文件                   | 能否编辑             | 适合交给谁       |
| ---------------------- | -------------------- | ---------------- |
| `.boxproject` 地图工程 | 可以                 | 作者、可信协作者 |
| 游玩部署包             | 不可以直接导回编辑器 | 服主             |
| 玩家网址               | 不可以编辑           | 普通玩家         |

游玩端可以阻止玩家把发布包直接当作工程重新打开，但浏览器仍需下载场景实际使用的模型、
贴图和音频。不要把未发布素材、私钥或真正的秘密写进作品资源；重要规则应在权威运行时中
执行。

## 数据位置

创作端默认把每个工程保存到：

```text
apps/local-engine/projects/<project-id>/
```

不要手动修改其中的 `project-state.json`、`blobs/` 或发布清单。备份和迁移请使用作品管理器
提供的导入、导出功能。

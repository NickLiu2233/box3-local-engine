# 作品创建、编辑与发布

创作者日常只使用创作端的作品管理器，不需要手动操作工程文件或分别启动其他程序。

## 打开创作端

在仓库根目录执行：

```bash
pnpm dev
```

然后打开：

```text
http://127.0.0.1:3002/
```

Docker 部署创作端可使用：

```bash
pnpm creator
```

## 创建作品

1. 点击右上角“新建作品”。
2. 填写作品名称。
3. 可继续填写作者、简介、封面、版本号和更新说明。
4. 保存后，作品会出现在作品列表中。

每个作品都有独立工程目录，不会与其他作品共用世界状态。

## 编辑与预览

- 点击“编辑”会在新页面打开该作品的编辑器。
- 点击“游玩”会在新页面打开当前工程预览。
- 编辑器保存或自动保存后，作品管理器会记录最新世界版本。
- 切换作品时，创作端会自动切换内部运行时，不需要手动改端口。

发布前请先在编辑器中保存一次。刚导入的工程也应先打开并保存，再进行发布。

## 编辑作品信息

在作品卡片的更多菜单中选择“编辑信息”，可以维护：

- 作品名称
- 作者
- 简介
- 封面
- 版本号
- 更新说明

这些信息会随可编辑工程包和游玩发布包一起导出，方便其他设备或服主识别作品。

## 换设备继续编辑

在作品菜单中点击“导出地图工程”，会下载：

```text
作品名称_项目ID.boxproject
```

在另一台安装了 Local Engine 的设备上打开作品管理器，点击右上角“导入工程”，直接选择
该文件即可。导入会创建新的本地工程，不会覆盖已有同名作品。

所有 `.boxproject` 都是地图组包；即使地图组当前只有一张主地图，也使用相同格式。从主地图或
任意副地图执行导出都会包含主地图、全部副地图和唯一共享资源根。导入时所有成员会一起创建，并获得一组新的本地项目 ID；地形、
实体仍按地图隔离，UI、图片、音频、项目模型、皮肤和共享脚本仍由地图组共享。

本地发行版不读取早期单地图归档结构。该格式从未作为发布格式交付，因此不保留兼容代码。

`.boxproject` 是可编辑工程包，只应交给作者或可信协作者。

## 发布作品

1. 确认编辑器已经保存。
2. 在作品菜单中点击“发布”。
3. 填写新版本号和更新说明。
4. 确认发布。

发布会生成不可变的游玩快照。工程之后继续修改，不会改变已经发布的版本；需要更新时请
发布新的版本号。发布清单会固定当时的地图组共享 revision，因此同一地图组的不同地图应在
共享资源修改完成后分别重新发布，避免部署不同时间生成的共享快照。

## 导出游玩部署包

在作品菜单中选择“发布为游玩包”。发布成功后会同时生成部署包；部署包只包含指定发布
版本，不包含可编辑的 `source/` 工程、作品管理器或编辑器。

创作端不会构建游玩镜像。第一次导出包含 `play-image.tar` 的部署包前，先在仓库根目录执行：

```bash
pnpm play
pnpm creator:up
```

第一条命令只准备并启动游玩端镜像；第二条命令使用已有镜像返回创作端。之后只要游玩镜像
版本没有变化，就不需要重复构建。默认镜像架构为 `linux/amd64`；目标服主是 ARM 服务器时，
应先设置 `BOX_PLAY_PLATFORM=linux/arm64`，再执行 `pnpm play`。

服主进入部署包目录后执行：

```bash
docker load -i play-image.tar
docker compose up -d
```

玩家只需打开：

```text
http://服务器地址:3000/
```

网页、资源和多人连接都走这一个地址，不需要再开放第二个游戏端口。

## 删除作品

删除操作会先显示项目内确认弹窗。确认后会删除本机的可编辑工程和该工程保存的发布版本。
重要作品请先导出 `.boxproject` 备份。

## 恢复历史版本

Local Engine 会在打开、导出和发布工程时自动保存有效快照，最多保留最近 5 份。在作品卡片
的更多菜单中选择“恢复历史版本”，可以查看快照产生时间、原因和大小，并恢复指定版本。

恢复前会先保护当前有效工程，因此误恢复后仍可从恢复记录切回。已经打开的编辑器不会被
强制刷新；恢复完成后请关闭旧编辑页并重新打开工程。

## 工程与发布包的区别

| 文件 | 能否编辑 | 适合交给谁 |
| --- | --- | --- |
| `.boxproject` 地图工程 | 可以 | 作者、可信协作者 |
| 游玩部署包 | 不可以直接导回编辑器 | 服主 |
| 玩家网址 | 不可以编辑 | 普通玩家 |

游玩端可以阻止玩家把发布包直接当作工程重新打开，但浏览器仍需下载场景实际使用的模型、
贴图和音频。不要把未发布素材、私钥或真正的秘密写进作品资源；重要规则应在权威运行时中
执行。

## 数据位置

创作端默认把每个工程保存到：

```text
apps/local-engine/projects/<project-id>/
```

不要手动修改其中的 `project-state.json`、`blobs/` 或发布清单。备份和迁移请使用作品管理器
提供的导入、导出功能。

# 地图作品、地图组与发布包

Creator 界面把可编辑项目称为“作品”，Play 界面把发布后的内容称为“地图”。底层数据模型一致：一个地图组包含一个主地图和零到多个副地图。

## 打开 Creator

源码开发：

```bash
pnpm dev
```

默认访问 `http://127.0.0.1:3002/`。Docker 运行使用 `pnpm creator`；桌面用户从启动器选择“创作端”或“全部”。

## 创建和编辑

1. 在作品页点击“新建作品”。
2. 选择地图大小，填写名称，并按需填写作者、简介和封面。
3. 打开编辑器制作地图，保存后可从作品页预览。
4. 需要多个场景时，在主地图下创建副地图。副地图同样可选择地图大小。

主地图和副地图各自保存地形、实体、脚本入口和运行状态。地图组可共享 UI、图片、音频、模型、皮肤、共享脚本和组数据空间。删除或替换共享资源前，应确认全部成员都已不再引用它。

## 编辑作品信息

主地图卡片的更多菜单可维护地图组对外信息，包括名称、作者、简介、封面、版本号和更新说明。副地图可维护自己的名称、简介等成员信息；作者以地图组发布信息为准。

Play 导入后不会提供这些字段的编辑功能。需要修改时应回到 Creator 修改、重新发布并导入新 `.boxplay`，以保护发布包的作者信息和内容完整性。

## `.boxproject`：继续编辑

从主地图或副地图菜单导出工程时，下载：

```text
作品名称_项目ID.boxproject
```

`.boxproject` 是可编辑工程包，应只交给作者或可信协作者。从地图组任一成员选择“导出完整地图组”，都会包含主地图、全部副地图、成员关系、导出入口和共享资源根。

导入时有两种归属方式：

- **作为独立地图组**：导入全部成员，为整组分配新的本地 ID，保留主副关系。
- **成为现有地图的副地图**：取导出入口地图作为新副地图，并让它使用目标地图组的共享资源库。

导入不会按名称覆盖现有作品。若目标是更新另一台设备上的旧工程，请先备份并明确删除旧副本，不要手工合并工程目录。

## `.boxplay`：交付游玩端

发布前先确保地图组所有成员都已保存。然后从主地图菜单发布整个地图组：

1. 填写版本号和更新说明。
2. Creator 校验每张地图并生成同一版本的不可变快照。
3. 下载一个 `.boxplay` 文件。
4. 服主在 Play 的服主管理界面导入该文件。

Play 会在正式安装前打开审查页，展示地图组成员以及已识别的代码、图片、音频和模型资源。审查内容保存在服务端临时目录，不执行脚本，只有服主确认后才会原子写入 Play 地图库。未被资源索引引用的系统 Blob 会单独计数，不会被猜测为可执行内容。

发布是地图组级原子操作；任一成员失败时不会留下半个发布版本。发布后继续编辑工程不会改变既有 `.boxplay`，更新必须生成新版本并重新导入。

`.boxplay` 包含主地图、副地图、成员关系和运行所需数据，但不包含可编辑 `source/`、Creator、VOXA、Docker 镜像或桌面 App。镜像由发行包提供，地图数据由 `.boxplay` 提供。

### 资源方式

| 方式       | 特点                            | 适用场景                             |
| ---------- | ------------------------------- | ------------------------------------ |
| 仅本地资源 | 运行资源写入 `.boxplay`，包较大 | 完全离线、长期归档、云端服务可能下线 |
| 仅引用 OSS | 包保留资源 hash 和公开 CDN 地址 | 发布者长期维护自己的 S3 兼容对象存储 |

OSS 的 Endpoint、Bucket、Access Key 和 Secret Key 只保存在发布者 Creator 的本地配置中，不写入 `.boxplay`。包中只包含公开资源地址和 hash，Play 下载后会校验内容。需要避免外部依赖时选择“仅本地资源”。

## Play 中的管理边界

服主导入 `.boxplay` 后可以：

- 在导入前审查地图信息、代码和媒体资源；
- 查看主地图和副地图；
- 临时关闭或重新开启整个地图组；
- 删除副地图或整个地图组。

关闭后地图不会出现在首页，直接访问地图 URL 也会被拒绝。Play 不提供地图编辑或地图包导出，也不允许修改封面、标题、简介和作者。设置 `BOX_PLAY_LIBRARY_READ_ONLY=true` 后，网页服主管理入口及导入、删除、开关接口都会关闭。

## 快照与删除

Creator 会在打开、导出和发布等关键动作前后保存有限数量的有效快照。恢复历史版本后，应关闭旧编辑页并重新打开工程，避免浏览器仍持有恢复前状态。

删除作品会移除本机可编辑工程及其本地发布记录。重要作品应先导出 `.boxproject`，并把备份保存到与工作目录不同的磁盘。

## 文件区别

| 内容           | 可编辑                   | 交付对象         |
| -------------- | ------------------------ | ---------------- |
| `.boxproject`  | 是                       | 作者、可信协作者 |
| `.boxplay`     | 否                       | Play 服主        |
| 桌面离线包     | 不包含用户地图           | 桌面部署者       |
| 无图形服务器包 | 不包含用户地图和创作工具 | Linux 服主       |
| 玩家网址       | 否                       | 普通玩家         |

浏览器运行地图时仍需读取场景实际使用的模型、贴图和音频。客户端脚本直接运行在玩家浏览器中，
可以被查看、修改或通过浏览器扩展干预；编辑器显示的引擎/浏览器 DTS 只是开发提示，不是运行时
权限系统。不要把私钥、访问凭证、账号判定或必须保密的规则放入客户端脚本或地图资源；胜负、
奖励、权限和持久存档等权威逻辑应在服务端脚本中执行，并验证来自客户端的所有输入。

## 本地数据位置

Creator 工程默认位于：

```text
apps/local-engine/projects/<project-id>/
```

不要手工修改 `project-state.json`、`blobs/`、地图组状态或发布清单。备份、迁移和交付使用 Creator 提供的导入、导出和发布功能。
